# 试玩记录（2026-10-03）

本轮按“试玩代理发现问题 → 实现代理修复 → 试玩代理独立复测”协作。试玩代理尝试初始化 computer-use 浏览器工具，但工具启动失败（`windows sandbox failed: helper_unknown_error`）。以下证据来自执行真实 `dist/app.js`、`dist/feedback-ui.js` 的 DOM/VM 交互模拟，**不是浏览器视觉验收**。API 响应使用可控替身，未读取密钥、未调用付费 AI。

## 已通过的完整游戏流程

- 同一题连续换题两次；第三次不再换题，题号仍为第一题，记录数仍为零。
- 换题后重新加载前端代码，恢复当前题目和已耗尽的换题次数。
- 完成七题：六题匹配题库答案，一题跳过；每题产生一条记录，跳过为零分。
- 每题连续点击两次“继续”，不跨过未答题、不重复记分；最后正确进入七题成绩页。
- 成绩页模拟“AI 新一轮”失败，原成绩和记录保留；题库再开局清空本轮记录并恢复两次换题机会。

## 1. 已保存反馈原因未同步，复核发送旧原因

- 操作：创建同一题、同一参考答案和分值的两组反馈控件 A、B（对应重复展示或两个标签页）；A 点踩，B 正确同步点踩状态；A 将反馈原因改为“事实错误”；在 B 点击 AI 复核。
- 修复前：浏览器存储中的原因已是“事实错误”，B 下拉框仍是“冷门度不合理”，请求正文 `concern` 也为“冷门度不合理”。
- 期望：同一条反馈的控件显示一致的已保存原因，复核针对当前原因。
- 复现：真实 `feedback-ui.js` 的事件处理器与可控 `gameFetch`；模拟下拉框明确设置浏览器默认首项，避免 DOM 替身差异影响结果。

## 2. 读取失败时，新反馈覆盖原有记录

- 操作：预先保存一条屏蔽题目反馈；注入 `getItem(FEEDBACK_STORAGE)` 读取异常、`setItem` 仍可执行的存储故障；给另一道题点赞；恢复读取并检查存储。
- 修复前：执行一次写入，原屏蔽记录消失，仅剩新赞；控件显示“已赞”。
- 期望：不能读取原有记录时不执行覆盖写入，提示保存失败并保留既有反馈。
- 限制：这是故障注入验证，不表示在真实浏览器中观察到了此存储故障。

## 3. 改赞／踩时丢失已选择的反馈原因

- 操作：点踩，选择“事实错误”，改赞，再改踩。
- 修复前：下拉框仍显示“事实错误”，已保存原因却被初始空值覆盖；重新加载后丢失原因。
- 期望：改票保留这条反馈已经选择的原因。

## 修复后的独立复测

试玩代理使用原复现脚本重新执行真实前端，结果如下：

- A 修改原因后，A、B 下拉框及已保存原因均为“事实错误”；B 的复核请求发送“事实错误”。
- 读取旧反馈失败时，未执行任何写入，旧屏蔽题记录保留，显示保存失败。
- 点踩 → 修改原因 → 点赞 → 点踩后，存储仍保留“事实错误”。
