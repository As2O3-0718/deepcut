# AI 出题修复验证（2026-10-03）

用户报告三批生成后仅筛得六题、五类。本轮检查出题过程，保留七题、至少五个大类、每类最多两题的要求。

## 观察到的问题

修复前实际 DeepSeek 测试：首批请求十个候选，五个与现有题库重复；第二批仍返回首批已经过滤的题。旧策略在只缺一题时仅请求两个候选，且失败后不保存已通过候选。该次实际调用经过三批后成功，不是对用户具体历史的复现；六题、五类的失败及续接由可控回归场景验证。

## 改动

- 补题批至少请求三个方向、六个候选，明确候选数可以大于缺题数。
- 优先尚未尝试的缺少类别，提供不同知识集合的方向；按本批方向精简提示中的排除清单。完整排除集合仍由服务端检查。
- 将重复及格式不合格题的原因交回下一批，修正系统格式示例，要求四至六个不同参考答案。
- 出题使用独立的温度配置，判题和复核保持原配置。
- 有效候选按排除集合的 SHA-256 指纹保存，20 分钟内续接，最多20组。不保存玩家完整历史，也不将半成品替换成题库题。
- 云端服务重启后可恢复候选；完成后移除草稿。前端缺题时显示“继续补齐 AI 题目”。

## 验证

97 项自动测试全部通过，包含六题五类失败后保存、服务重启续接、不同排除集合隔离、过期清理、错误反馈、JSON 截断重试、前端保留原局及按钮提示。

实际 DeepSeek 本机测试首批即凑齐七题、五类。部署 Cloudflare Worker 后，连续两轮线上测试均成功：第一轮一批、七题五类；第二轮两批、七题七类。第二轮排除了第一轮题目，完整结果均通过格式、重复和类别配额检查。

实际 API 返回及诊断脚本仅存在忽略的 `.local/round-diagnostics/`，不进入公开仓库。测试只说明这些样本通过；模型生成仍可能失败或包含事实错误，保留严格校验和续接机制。
